## 1. 프로젝트 개요

### 1.1 제품 정의
**마이링크(MyLink)**는 개인 크리에이터와 일반 사용자가 자신의 다양한 SNS(유튜브, 인스타그램, 틱톡 등), 블로그, 포트폴리오 링크를 한곳에 모아 단 하나의 고유 URL로 공유할 수 있도록 지원하는 **링크트리(Linktree) 클론 서비스**입니다.

### 1.2 핵심 가치 (Core Value)
1. **단 하나의 대표 주소**: SNS 프로필 소개란에 `/[username]` 단일 링크만 등록하여 모든 활동 채널로 트래픽 유도
2. **네오브루탈리즘(Neo-brutalism) 아이덴티티**: 4주차에 구현된 볼드한 테두리와 하드 섀도우 기반의 감각적인 디자인 계승
3. **간결한 링크 관리**: 복잡한 설정 없이 링크 등록, 수정, 삭제 및 위·아래 버튼을 통한 순서 조정을 `/admin`에서 손쉽게 수행

### 1.3 타겟 사용자
- **주요 사용자**: SNS와 콘텐츠 채널을 다수 운영하며 프로필 링크 허브가 필요한 **개인 크리에이터 및 인플루언서**
- **일반 사용자**: 협업 문의, 포트폴리오, 명함 링크를 깔끔하게 전달하고자 하는 개발자, 디자이너, 프리랜서 등

## 2. URL 구조 및 서비스 흐름

### 2.1 라우팅(URL) 구조
| 구분 | URL 경로 | 접근 권한 | 설명 |
| :--- | :--- | :--- | :--- |
| **메인 홈 / 랜딩** | `/` | 모든 사용자 | 서비스 소개 및 구글 로그인 진입점 |
| **공개 프로필** | `/[username]` (예: `/sakdasdm`) | **모든 방문자 (비로그인)** | 크리에이터의 프로필 및 링크 모음 열람 |
| **관리자 페이지** | `/admin` | **로그인된 소유자** | 내 프로필 정보 및 링크 추가/수정/삭제/순서 관리 |

---

### 2.2 사용자 핵심 흐름 (User Journey)

서비스의 주 사용자인 **방문자**와 **소유자(크리에이터)**의 이용 흐름을 단계별로 정의합니다.

#### 시나리오 1: 방문자 흐름 (Visitor Flow)
1. **프로필 접속**: 인스타그램, 유튜브, 블로그 등 SNS 소개글에 공유된 프로필 링크(예: `/sakdasdm`)를 클릭하여 접속한다.
2. **콘텐츠 탐색**: 별도의 회원가입이나 로그인 없이 크리에이터의 프로필(사진, 닉네임, 소개)과 등록된 링크 목록을 확인한다.
3. **외부 링크 이동**: 원하는 링크 카드를 클릭하면 해당 웹사이트가 새 탭에서 열려 손쉽게 콘텐츠를 소비한다.
   *(필요 시 상단 '공유' 버튼을 눌러 프로필 URL을 클립보드에 복사할 수 있다.)*

#### 시나리오 2: 소유자 흐름 (Owner Flow)
1. **로그인 및 관리자 진입**: 마이링크 메인 화면에서 구글 계정으로 로그인하여 관리자 페이지(`/admin`)로 들어간다. *(최초 로그인 시 고유 username 설정)*
2. **링크 추가 및 정보 수정**: 새로운 활동 링크(아이콘, 제목, URL)를 추가하고, 기존에 등록된 링크의 제목이나 URL을 최신 정보로 수정한다.
3. **링크 삭제 및 순서 조정**: 더 이상 쓰지 않는 불필요한 링크를 삭제하고, 각 링크의 **위(▲)·아래(▼) 버튼**을 눌러 표시 순서를 바꾼다.
4. **저장 및 결과 확인**: 변경된 내용을 저장한 뒤, 자신의 공개 프로필(`/[username]`)에 접속하여 수정된 내용과 정렬된 링크 순서가 제대로 반영되었는지 확인한다.

## 3. 기능 요구사항 명세 (Functional Requirements)

### 3.1 회원가입 및 인증 (Firebase Authentication)
- **[F-101] 구글 소셜 로그인**:
  - Firebase Authentication의 Google Auth Provider를 사용하여 비밀번호 없는 원클릭 로그인 구현.
- **[F-102] 고유 사용자명(Username) 설정 및 검증**:
  - 첫 로그인 시 URL 경로로 사용할 영문/숫자 기반의 `username` 등록 (중복 방지 유효성 검사 수행).
- **[F-103] 접근 권한 제어**:
  - `/[username]` 페이지는 비로그인 방문자 누구나 열람 가능.
  - `/admin` 경로는 로그인한 소유자 본인만 접근 가능하며, 비로그인 사용자는 로그인 페이지로 리다이렉트.

---

### 3.2 공개 프로필 페이지 (`/[username]`)
- **[F-201] 프로필 헤더**:
  - **프로필 사진**: 크리에이터 프로필 이미지 (미등록 시 기본 아바타).
  - **닉네임 및 한 줄 소개**: 사용자가 설정한 이름과 소개글 노출.
  - **프로필 공유 버튼**: 클릭 시 현재 페이지 주소를 클립보드에 복사하고 "복사 완료!" 알림 표시.
- **[F-202] 링크 버튼 목록 표시**:
  - **정렬 기준**: 관리자(`/admin`)에서 **마지막으로 저장한 순서**와 완전히 동일하게 세로 배치로 표시.
  - **링크 구성 요소**: 좌측 아이콘 + 링크 제목 + 부가 설명/배지 + 우측 외부 링크 화살표 아이콘.
  - **새 탭 열기**: 링크 버튼 클릭 시 대상 URL이 새 탭(`target="_blank"`, `rel="noopener noreferrer"`)에서 실행.
- **[F-203] 반응형 지원**:
  - 모바일(스마트폰) 환경에 최적화된 최대 너비 420px 중심의 카드 컨테이너 레이아웃.

---

### 3.3 관리자 페이지 (`/admin`)
- **[F-301] 프로필 기본 정보 수정**:
  - 닉네임, 한 줄 소개(Bio) 입력 및 수정.
- **[F-302] 링크 CRUD (생성·조회·수정·삭제)**:
  - **추가 (Create)**: 새 링크(제목, URL, 아이콘) 등록.
  - **조회 (Read)**: 현재 등록된 링크 목록을 저장된 순서대로 표시.
  - **수정 (Update)**: 기존 등록된 링크의 제목, URL, 아이콘 정보 수정.
  - **삭제 (Delete)**: 불필요한 링크 삭제 기능.
- **[F-303] 위·아래 버튼 순서 변경**:
  - 각 링크 항목의 **▲(위로 이동) / ▼(아래로 이동)** 버튼을 클릭하여 링크 순서 조정.
  - 최상단 항목은 위로 이동 비활성화, 최하단 항목은 아래로 이동 비활성화.
- **[F-304] 저장 및 즉시 반영**:
  - `/admin`에서 저장 버튼을 누르면 Cloud Firestore에 순서 정보(`orderIndex`)가 갱신되며, 공개 프로필(`/[username]`)에 즉시 반영.

## 4. UI/UX 디자인 명세 (Design Specification)

- **디자인 테마**: **네오브루탈리즘 (Neo-brutalism)** (4주차 기구현 디자인 100% 유지)
- **스타일 가이드라인**:
  - **테두리**: 선명하고 두꺼운 2px~3px 검은색 외곽선 (`border-2 border-black`, `border-[3px] border-black`)
  - **그림자**: 블러 없는 단색 하드 드롭 섀도우 (`shadow-[2px_2px_0px_0px_#000]`, `shadow-[4px_4px_0px_0px_#000]`, `shadow-[6px_6px_0px_0px_#000]`)
  - **컬러 팔레트**:
    - 배경: 생동감 있는 옐로우 (`bg-[#FEF08A]`)
    - 프로필 컨테이너: 클린 화이트 (`bg-white`)
    - 배지 및 포인트: 민트(`bg-[#A7F3D0]`), 스카이블루, 앰버, 바이올렛
  - **인터랙션 피드백**:
    - 호버 시 미세 대각선 이동 (`hover:-translate-x-0.5 hover:-translate-y-0.5`)
    - 클릭/활성 상태 시 물리적으로 꾹 눌리는 효과 (`active:translate-x-1 active:translate-y-1 active:shadow-[1px_1px_0px_0px_#000]`)

## 5. 데이터 저장소 설계 (Cloud Firestore)

데이터베이스는 Google Cloud Firestore를 사용하며, NoSQL 문서-컬렉션 구조로 설계합니다.

### 5.1 `users` 컬렉션
- 문서 ID: Firebase Auth UID
```json
{
  "uid": "FIREBASE_AUTH_UID",
  "email": "user@gmail.com",
  "username": "sakdasdm",
  "displayName": "김경원",
  "bio": "새로운 기술을 탐구하고 지속적으로 성장하는 개발자입니다.",
  "photoURL": "https://...",
  "createdAt": "Timestamp"
}
```

### 5.2 `links` 서브컬렉션 (`users/{uid}/links/{linkId}`)
- 각 사용자 문서 하위의 서브컬렉션으로 링크를 격리 관리
```json
{
  "id": "AUTO_GENERATED_ID",
  "title": "GitHub",
  "url": "https://github.com/sakdasdm",
  "icon": "github",
  "description": "프로젝트 소스 코드와 커밋 잔디 보러가기",
  "badge": "GitHub",
  "orderIndex": 0,
  "clickCount": 0,
  "createdAt": "Timestamp",
  "updatedAt": "Timestamp"
}
```
*※ 공개 프로필(`/[username]`) 조회 시 `orderIndex` 오름차순으로 쿼리하여 마지막 저장 순서를 보장합니다.*
